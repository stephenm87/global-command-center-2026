# Known Issues

1. **GDELT Upstream Availability**: Browser calls to GDELT are now routed through a CDN-cached Netlify proxy (`netlify/functions/gdelt-pulse.mjs`) with allowlisted topic queries and a `5s` timeout, degrading gracefully to `{ articles: [] }` if upstream GDELT rate-limits or stalls.
2. **Distributed Rate Limiting**: Provider functions require authentication, cache rejected tokens locally, and apply per-endpoint user limits plus classroom-safe post-auth IP ceilings in memory, but durable cross-instance limits across cold serverless containers still require a shared store.
3. **Email Verification**: Magic-link email delivery depends on external Supabase SMTP/Auth configuration and redirect allowlists (`docs/SUPABASE.md`).
4. **Supabase RLS Deployment Verification**: A versioned, idempotent Row Level Security migration now lives in `supabase/migrations/20261116000000_user_data_rls.sql`, but applying and verifying it against the live production Supabase database remains an operational step.
5. **Deferred 3D Chunk Size**: The main application shell was reduced to ~`287 kB` (`94.6 kB` gzip) with `case-studies` (`173.9 kB`, `50.2 kB` gzip) split into its own separately cacheable chunk and 1-tap WebGL Globe opt-in on mobile viewports (`<768px`), while the deferred Three.js rendering chunk (`~1.34 MB`, `361.8 kB` gzip) still loads on desktop Globe and opt-in 3D Nexus views.
6. **Editorial Ownership and Claim Review Automation**: The 29 case studies carry `updatedAt`, `reviewCadenceDays`, `reviewBy`, sensitivity, and uncertainty metadata, `npm run content:staleness` reports overdue and upcoming `reviewBy` dates, and daily link checks run via `refresh-source-health` (`24s` inline deadline-bounded check at `5,000ms` timeout / `concurrency = 4` / `maxPerHost = 2`, plus `refresh-source-health-background` 15-minute worker at `8,000ms` timeout with a `36h` staleness safety net — verified live on PR #34 Netlify deploy preview with `CRON_SECRET` set: `127` pre-remediation active links checked in `21.4s`, `0` deferred, `90` healthy / `31` restricted / `0` broken / `6` unknown; manifest now tracks `140` targets). All `20` `high`-sensitivity or `<=14d`-cadence cases scheduled for pre-pilot renewal (`3` Phase 0 repairs + `17` substantive renewals, excluding `tuvalu-australia-falepili-union` which had no material Aug–Nov 2026 status change) have been substantively rechecked through `2026-11-16`/`17`, while `tuvalu-australia-falepili-union` (`2026-08-10`) and the `8` remaining `standard`-sensitivity (`30–90d`) overdue cases (`9` total) display an explicit `"Last reviewed <date>, update in progress"` notice across Guided Briefings and Globe cards until renewed during upcoming batches. However, the application still does not assign a named editorial owner, open claim-review tasks, send automated reminders, or automatically verify that claims continue to match source content; the cases remain dated editorial snapshots rather than a live monitoring service.
7. **Relationship Provenance**: Dated case connections include sources, but the advanced 3D Nexus also contains legacy structural annotations that are reference context rather than independently sourced current claims.
8. **Vite 5 Development Advisories**: The repository contract currently requires Vite 5 (`5.4.x`). Non-breaking `npm audit fix` resolved the fixable transitive advisories (`@fastify/busboy`, `nanoid`, `source-map-js`), leaving Vite 5 development-server path/CORS/middleware and `esbuild` advisories that have no fix inside Vite 5. Vite is not included in the Netlify production runtime and local `dev`/`preview` bind to `127.0.0.1`, but moving to a supported Vite major requires an explicit repository-policy update.
9. **Automated Feed Language and Claim Limits**: The public snapshot balances seven regions, six issue lenses, and five source roles, but discovery remains English-language and provider-dependent. Automated relevance, source-role classification, and link availability do not verify article claims or eliminate editorial bias.
10. **Firecrawl Upstream DNS Resolution**: `deep-scan.js` upgrades `http:` URLs to `https:`, blocks private/reserved IP literals and rebinding suffixes, and runs a best-effort `1.5s` DNS pre-check, but Firecrawl resolves DNS independently on its own servers when fetching articles.
